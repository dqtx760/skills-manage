# 客户案例短文案

根据微信聊天记录，生成适合发朋友圈的客户案例短文案。

## 工作流程

### 步骤一：识别客户

用户提供以下任意一种：
- **直接给出姓名/昵称**：如"张建伟"、"李明" → 直接用 wx-cli 查询
- **提供聊天记录文本**：直接进入步骤二
- **只给需求描述**：如"帮我写个客户案例，关于帮我装 Claude Code 的那个人" → 尝试用 wx-cli 搜索相关会话

### 步骤二：读取聊天记录（如需要）

如果用户指定了姓名，且提供了 wx-cli 环境，执行：

```bash
# 搜索客户
wx search "客户姓名"

# 读取聊天记录（最近50条，根据实际情况增减）
wx history "客户姓名" -n 50
```

如果 wx-cli 未初始化或无法连接，告知用户："wx daemon 未运行，请先运行 `wx init` 初始化"。

### 步骤三：生成文案

基于聊天记录，按下方框架生成文案。

## 输入

- **有 wx-cli + 客户姓名**：自动读取聊天记录，用户无需提供额外信息
- **有聊天记录文本**：直接基于文本生成
- **有上下文描述**：结合上下文 + 聊天记录（如有）综合生成

## 输出要求

生成 **2 个版本**，字数控制在 200-400 字，适合朋友圈阅读节奏：

- **版本①**：叙事风格，讲故事为主
- **版本②**：简洁干练，信息密度高

## 固定文案框架（必须遵循）

每个版本严格按此结构展开，**顺序不可调换**：

```
① 获客来源：客户从哪里找到我的
② 客户需求：他遇到了什么问题/有什么需求
③ 服务内容：我具体做了什么
④ 客户认可：他的原话/反馈
```

**示例框架：**

> 昨天有个客户从抖音上找到了我，
> 想让我帮他安装 Claude Code。
>
> 他有两个真实需求：
> 一是公司公众号文章写作、视频号竞品分析、脚本撰写
> 二是代理 vivo 手机，经销商核销数据的分析
>
> 他不会科学上网，不会用命令行，连注册账号都卡壳。
>
> 于是我远程给他搭了一套：
> Claude Code + Obsidian 集成 + 3 个自动化 Skill + WorkBuddy 备用界面。
>
> 他非常满意，他说：
> "你的能力就是很多很多人的需求，不做自媒体真浪费了。"

## 文案风格规则

1. **真实感第一**：引用客户原话，不编造，不夸大
2. **不说教**：用故事带出价值，不直接写"我很专业"
3. **口语化**：朋友圈是私人场景，不是公众号，语气要像在和人说话
4. **客户来源必须交代**：抖音、小红书、朋友推荐、主动找上门……让读者知道客户是怎么来的
5. **客户需求要具体**：不是"有需求"，而是"他需要做某某事但卡住了"
6. **服务内容要清晰**：不是"提供了服务"，而是"搭了 A + B + C"
7. **结尾落点**：要么有趣、要么共鸣、要么引发好奇，禁止空喊口号
8. **禁止**：过度营销话术、空洞形容词（"顶尖"、"顶级"、"震撼"）、emoji 堆砌

## 提取技巧

从聊天记录中重点关注：

| 素材类型 | 价值 | 位置 |
|---|---|---|
| 客户怎么找到你的 | 建立信任感 | 第一句 |
| 客户的困惑/卡点 | 引发共鸣 | 开头 |
| 客户的具体需求 | 展示服务针对性 | 第二段 |
| 解决过程 | 展示专业 | 核心段落 |
| 客户原话评价 | 信任背书 | 结尾，加引号 |

## 写作检查清单

- [ ] 第一句交代了获客来源？
- [ ] 客户需求说清楚了吗？
- [ ] 我做了什么服务讲明白了吗？
- [ ] 引用了客户原话吗？
- [ ] 字数在 200-300 字之间？
- [ ] 没有空洞形容词和 emoji 堆砌？

## 特别注意

- 如果聊天记录中有客户的**微信昵称**或**职业背景**，在文案中合理使用（可模糊处理）
- 如果客户明确表示不希望公开，删除敏感信息或改写
- 多引用**有画面感的具体细节**，少用抽象描述
- wx-cli 使用参考：
  - `wx init`：首次初始化（需要微信运行，Windows 需管理员权限）
  - `wx search "关键词"`：搜索联系人/消息
  - `wx history "名称" -n 50`：读取最近50条聊天记录
  - `wx daemon status`：检查后台状态
